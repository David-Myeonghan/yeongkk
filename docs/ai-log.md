# AI와 일한 기록

> 결론: 계획 · 조사 · 구현 초안은 AI(Claude Code)에게 맡기고, 결정과 계정 · 화면 확인은 직접 했다.
> AI가 틀린 것은 대부분 「기억으로 적은 바깥 사실」이었고, 실제 화면이나 공식 문서와 맞대 봤을 때 드러났다.

상태: 초안(AI가 씀). David 검토 전. 「직접 한 것」과 「알아챈 방법」은 David가 고쳐야 정확하다.

## 2026-11-19

**맡긴 것:** 단어 등록 검사 8개, 묶기, PR 검사 워크플로.

**AI가 틀린 것:** 검사 워크플로가 PR이 가져온 검사기를 그대로 실행했다. PR이 검사기 자체를 고치면 초록으로 통과한다.

**알아챈 방법:** 일부러 검사기를 고치는 PR(#4)을 열어 봤다. 통과했다.

**고친 것:** 워크플로를 `pull_request_target`으로 바꿨다. 검사기 · 금칙어 · 워크플로는 언제나 main의 것을 쓰고, PR에서는 `words/` 데이터만 가져온다.

## 2026-11-22

**맡긴 것:** 일주일 계획(갈래 10개), 호스팅 후보 비교, 브릿지 규약 사양과 테스트, Cloudflare 설정 안내.

**직접 한 것:** 방향 결정(웹뷰, 스택, 범위). Cloudflare 가입과 토큰 발급. 화면이 안내와 다를 때 캡처로 되묻기.

**AI가 틀린 것과 알아챈 방법:**

| 틀린 것 | 어떻게 알아챘나 | 그대로 갔으면 |
| --- | --- | --- |
| Cloudflare 토큰 권한을 기억으로 적었다(`Workers Scripts: Edit`, `Cloudflare Pages: Edit`) | 대시보드 화면에 둘 다 「레거시」로 표시돼 있었다. 공식 문서를 다시 읽게 했다 | 권한 체계가 두 달 전에 바뀌어 있었다. 적어 준 권한으로는 없는 Worker를 만드는 첫 배포가 실패한다 |
| 호스팅 후보에서 AWS와 Supabase를 빼놓았다 | 「고려했어?」라고 물었다 | 선택 근거가 「견준 적 없음」인 채로 남는다 |
| DB 쓰기 한도를 이벤트 1건 = 2행으로 계산했다(하루 약 3,300판) | 계획의 표 정의를 다시 대조했다. 색인이 둘이라 1건 = 3행이다 | 한계가 하루 약 2,200판인데 3분의 1을 더 잡는다 |
| 근거로 든 파일(`api/src/db.ts`)이 계획에 없었다 | 근거 문장과 계획의 파일 목록을 맞대 봤다 | 「나갈 길이 있다」는 근거가 빈말이 된다 |
| 구글 플레이 가입 조건에서 실물 안드로이드 폰 확인을 빠뜨렸다 | 「폰 없으면 못 하나?」라고 물었다 | 앱을 올리는 날에야 막힌다 |
| 서버 테스트 패키지를 옛 이름으로 적었다 | 구현 전에 공식 문서와 npm 정보를 대조했다 | 설치는 되지만 쓰는 테스트 실행기 버전과 맞지 않는다 |
| 퀴즈 로직의 단어 타입이 실제로 게시되는 파일과 달랐다(추가한 날짜가 게시 파일에 없음) | 구현을 시작하기 전에 작업끼리 주고받는 모양을 표로 대조했다 | 「이번 주 새 단어」를 가려낼 수 없다 |

**구현을 맡긴 방식(11-22 밤):** 작업 하나마다 구현하는 AI와 리뷰하는 AI를 따로 세웠다. 구현하는 쪽은 테스트를 먼저 쓰고, 리뷰하는 쪽은 구현 보고를 믿지 않고 diff만 본다.

| 리뷰가 잡은 것 | 그대로 갔으면 |
| --- | --- |
| 린터가 TypeScript 7을 못 받자 구현하는 AI가 컴파일러 둘을 별칭으로 같이 깔았다 | 뒤에 붙는 도구마다 어느 컴파일러를 볼지 따져야 한다. TS 6 하나로 정했다 |
| 앱이 자기 소개를 안 넣었을 때 웹이 `hello`를 묻지 않았다 | 옛 앱이 브라우저 취급을 받아 앱 공유가 안 뜬다 |
| 실험 배정 해시의 입력 글자 순서를 못 박는 테스트가 없었다 | 누가 순서를 바꿔도 테스트가 통과하고, 이미 배정된 사람이 다른 변형으로 넘어간다 |
| 설정의 `api` 값 검사가 `//남의주소`를 통과시켰다 | 설정 파일 한 줄로 이벤트가 다른 서버로 갈 수 있다 |
| 같은 검사를 고친 뒤에도 `/\남의주소`가 통과했다. 브라우저는 역슬래시를 `/`로 읽는다 | 위와 같다. 한 번 고친 곳을 다음 리뷰가 또 뚫었다 |
| 서버의 처리기가 던지면 JSON 대신 Cloudflare 오류 페이지가 나갔다 | 웹이 실패를 알아채지 못한다 |
| 제보 글 검사가 「어쩔.티비」는 막고 `kakao.com/o/x`는 통과시켰다. 내가(AI) 구현하는 AI에게 준 규칙 문장이 틀렸다 | 신조어 제보는 거절되고 오픈채팅 주소는 저장된다 |
| 버튼에 포커스 표시와 눌림 표시가 없었다. 다크 모드에서 브라우저 위쪽 색이 흰색이었다 | 키보드나 보조 기기로는 어디를 누르는지 보이지 않는다 |
| 단어와 설정을 같이 기다렸다. 설정 요청이 멈추면 홈이 영원히 불러오는 중이었다 | 설정 하나 때문에 퀴즈를 시작도 못 한다 |
| 날짜 테스트가 시간대를 못 박지 않았다. UTC로 도는 CI에서는 틀린 구현도 통과했다 | 자정 무렵에 「오늘」이 하루 어긋나도 테스트가 초록이다 |
| 일부 웹뷰에서 복사 기능이 반쯤만 있을 때 공유가 실패하고 화면에 아무것도 안 떴다 | 공유를 눌렀는데 반응이 없다 |
| 앱 공유 호출이 5초 제한을 썼다. 공유 창을 5초 넘게 열어 두면 웹 공유 창이 하나 더 떴을 것이다 | 공유 창이 둘 뜨거나 몰래 복사된다 |
| 「이벤트 서버가 답이 없어도 완주한다」 테스트가 이벤트를 아예 안 보내도 통과했다 | 이벤트 전송이 통째로 망가져도 테스트가 초록이다 |
| 배포 워크플로의 비밀값이 저장소 수준이었다. 검토 안 된 브랜치에서 손으로 돌리면 그 코드가 토큰을 받는다 | 자동 수집용 토큰이 생기는 날 배포 권한까지 새어 나간다 |

**배운 것:**

- 바깥 서비스의 메뉴 이름 · 권한 이름 · 한도는 그날 공식 문서로 확인한 것만 믿는다. AI에게도 「기억으로 적지 말고 문서를 읽고, 못 읽었으면 못 읽었다고 적으라」고 시킨다.
- AI가 낸 숫자는 계산의 입력(여기서는 색인 수)을 직접 맞대 본다.
- 계획을 실행하기 전에 작업끼리 주고받는 타입을 한 번 대조한다. 틀린 것 일곱 중 둘이 여기서 나왔다.
- 리뷰는 「구현한 쪽의 보고를 믿지 말고 diff를 보라」고 시킨다. 밤사이 리뷰 열다섯 번 가운데 열한 번에서 고칠 것이 나왔다.
- 테스트가 있다는 것과 테스트가 잡는다는 것은 다르다. 「틀린 구현으로 바꿔도 이 테스트가 통과하는가」를 물었을 때 통과하는 테스트가 셋 나왔다.
- 화면은 스크린샷을 찍어 눈으로 본다. 빌드가 된다는 보고만으로는 화면이 맞는지 모른다.
