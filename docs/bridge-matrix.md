# 웹과 앱 사이 규약 — 앱 버전별 동작 표

> 결론: 웹은 앱 버전을 보지 않는다. 쓸 수 있는 기능을 먼저 묻고, 없으면 웹 방식으로 대신한다.
> 아래 표의 「테스트」 칸은 전부 통과했다(2026-11-22). 「실기기」 칸은 앱 껍데기를 만든 뒤에 채운다.
> 이 문서가 말하는 코드와 테스트는 브릿지 PR(#7)에 있다. 그 PR이 합쳐지기 전에는 `main`에 없다.

상태: 초안(2026-11-22, AI가 씀). David 검토 전. 실기기 칸은 비어 있다.

## 왜 이 문제가 생기나

앱은 웹을 여는 껍데기다. 웹은 스토어 업데이트 없이 바뀐다.
그래서 한 달 전에 깐 앱이 오늘 바뀐 웹을 연다.
웹이 새 기능을 부르면 옛 앱은 그 요청을 모른다.

앱 버전 숫자로 갈라 쓰는 방법은 버렸다.
기능이 늘 때마다 「몇 버전부터 되나」 표를 웹이 들고 있어야 하고, iOS와 안드로이드가 어긋나면 표가 틀린다.

## 규칙 여섯

1. **기능은 묻고 쓴다.** 웹은 `has(이름, 최소 버전)`으로 확인한 기능만 부른다. 없는 기능은 보내지도 않는다.
2. **인사는 두 길.** 앱이 넣어 둔 자기 소개가 있으면 그것을 읽는다. 없으면 `hello`를 보내고 300ms만 기다린다. 답이 없으면 브라우저로 본다.
3. **더하기만 한다.** 새 기능과 새 필드는 추가만 한다. 받는 쪽은 모르는 필드 · 이벤트 · 메시지 종류를 버리고 죽지 않는다.
4. **기능마다 버전.** 기능의 뜻이 바뀌면 그 기능의 버전만 올린다. 규약 전체 버전은 메시지 모양이 깨질 때만 올린다.
5. **모든 요청에 시간 제한.** 답이 안 오면 `TIMEOUT`으로 끝내고 웹 방식으로 넘어간다. 늦게 온 답은 버린다.
6. **모르는 요청에는 반드시 거절로 답한다.** 앱은 모르는 이름에 `UNSUPPORTED`를 돌려준다. 조용히 무시하지 않는다.

## 공유가 넘어가는 순서

앱 공유 → 웹 공유 → 복사 → 없음.

- 앱 호출이 거절되거나 실패하면 웹 공유로 넘어간다.
- 앱 호출은 60초를 기다린다. 공유 창은 사람이 닫을 때까지 열려 있기 때문이다. 60초가 지나도 답이 없으면 거기서 끝낸다. 웹 공유로 넘어가지 않는다. 앱 공유 창이 떠 있는 채로 공유 창이 하나 더 뜨거나 몰래 복사되는 일을 막는다.
- 사용자가 웹 공유 창을 닫으면 거기서 끝낸다. 복사로 넘어가지 않는다. 닫은 것은 「안 하겠다」는 뜻이기 때문이다.
- 복사할 글이 없으면 복사하지 않는다.

## 리뷰에서 고친 것

테스트를 먼저 쓰고 구현했는데도 리뷰에서 둘이 나왔다.

- 앱이 자기 소개를 아예 안 넣었을 때 `injectedObjectJson()`이 `undefined`나 `"null"`을 줄 수 있다. 처음 구현은 이것을 「모르는 규약」으로 읽어 `hello`를 묻지 않았다. 옛 껍데기가 브라우저 취급을 받는 버그다. `react-native-webview` 문서의 「it may be `undefined`」 문장을 확인하고 고쳤다.
- 대신하기의 갈래(웹 공유 실패 → 복사, 복사 실패)에 테스트가 없었다. 넣었다.
- 앱 공유 호출이 기본 시간 제한(5초)을 썼다. 공유 창을 5초 넘게 열어 두면 시간 초과로 처리돼 웹 공유 창이 하나 더 떴을 것이다. 웹 화면에 붙이는 단계의 리뷰에서 나왔다. 60초로 늘리고, 시간 초과에서는 넘어가지 않게 바꿨다.

## 실기기에서 확인할 것(앱 껍데기 뒤)

- 자기 소개를 뺀 빌드에서 인사가 느린 길로 되는가.
- `share` 처리기를 뺀 빌드에서 공유가 웹 방식으로 넘어가는가.
- 안드로이드와 iOS에서 `injectedObjectJson()`이 실제로 무엇을 돌려주는가(문서는 「`undefined`일 수 있다」까지만 적는다).
