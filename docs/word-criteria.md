# 단어 수록 기준

> 결론: 서로 다른 곳 두 군데 이상에서 보인 말만 넣는다. 특정 집단을 비하하거나 혐오하는 말은 넣지 않는다. 애매하면 뺀다.
> 뜻 · 예문 · 유래는 직접 쓴다. 남의 설명 문장을 옮기지 않는다.

상태: 초안(2026-11-23, AI가 씀). David 확인 전. 계획 문서(2026-11-19)에 적힌 기준을 한 장으로 옮긴 것이다. 새로 정한 것은 없다.

## 넣는 말

- 서로 다른 출처 두 곳 이상에서 보인 말. 한 곳에서만 보이면 다음 주까지 기다린다.
- 자동 수집에서는 「플랫폼 두 개 이상에서 보임」으로 센다. 한 플랫폼 안에서만 도는 밈은 남지 않는다.
- 단어 파일의 `sources`에 허용된 플랫폼(YouTube · Instagram · TikTok)의 주소를 적는다. 서로 다른 플랫폼이 두 곳 이상이어야 한다. 다른 사이트의 주소는 거절된다. 검사 문지기가 이것을 본다.

## 넣지 않는 말

- 특정 집단을 비하하거나 혐오하는 은어.
- 금지어 목록에 걸리는 말. 목록은 로케일마다 따로 둔다.
- 판단이 애매한 말. 애매하면 뺀다.

## 쓰는 방법

- 뜻, 예문 둘, 유래 한 줄, 웃긴 오답을 직접 쓴다.
- AI로 초안을 받을 수 있다. 사람이 고치고 고른다.
- 뉴스레터나 매체의 설명 문장은 옮기지 않는다. 단어는 누구 것도 아니지만 설명 문장은 쓴 사람의 글이다.
- 검색 API로 받은 데이터 중 약관이 AI 활용을 막는 것은 AI에 넣지 않는다.

## 모으는 방법

- 사람이 주 1회 정해 둔 출처만 훑는다.
- 자동 수집은 공식 API가 있는 곳만 한다. 커뮤니티 사이트를 자동으로 긁지 않는다.
- 10~20대만 거르는 방법은 「누가 썼나」가 아니라 「어디서 모으나」다. 10~20대가 주로 보는 채널과 해시태그 목록을 정해 두고 거기서만 모은다.
- 말, 횟수, 공개 글 주소만 저장한다. 아이디 · 이름 · 글 원문은 저장하지 않는다. 미성년자의 글이 섞이기 때문이다.

## 등록하는 길

- 단어 하나는 파일 하나다(`words/ko-KR/<id>.json`).
- 등록은 그 파일을 추가하는 PR 하나다. 사람이 쓰든 자동 수집이 올리든 길이 같다.
- PR이 올라오면 자동으로 검사한다. 필수 칸, 같은 로케일 안의 중복, 금지어, 오답이 정답과 겹치는지, 예문에 그 말이 들어 있는지, 출처(허용된 플랫폼 · 서로 다른 두 곳), 개인정보(이메일 · @아이디 · 전화번호 · 계정 주소). 자동 수집이 올린 PR은 단어 파일만 바꿀 수 있다. 정확한 목록은 `registry/checks.ts`가 기준이다.
- 합치는 순간이 게시다.

## 내리는 방법

- 유행이 끝난 말은 지우지 않고 `status`를 `retired`로 바꾼다. 새 판에 나오지 않는다.

## 아직 안 정한 것

- 웃긴 오답을 모든 단어에 넣을지. 지금 스키마는 모든 단어에 한 개 이상을 요구한다. 처음 계획은 「100개 중 절반만 넣고 반응을 본다」였다.
- 제보로 들어온 말을 후보에 올리는 기준. 처음 계획은 「같은 말이 3번 이상」이다.
